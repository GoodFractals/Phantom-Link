What each proves

TLA+ / TLC

Checks Every reachable state of the model against named invariants.

Ours No LINK UP without ECDH keys; no zero session when up; keys need a session; pending needs HELLO.

Not The C code, the radio, or a model you forgot to write.

Z3

Checks Whether a logical/arithmetic statement has a counterexample (sat) or not (unsat).

Ours 85-glyph ceiling, queue depth, serial comparison asymmetry, wraparound, 8-slot window, ACK order.

Not Cryptographic strength, compiler correctness, or hardware behavior.

CBMC

Checks C code against assertions, with loops unwound to a fixed bound.

Ours Staged harness: frame decode bounds and encode/decode round-trip for 0–64 byte payloads.

Not Anything beyond the chosen bounds; not yet run here.

Vocabulary

  • Model: a simplified description you write. Proofs apply to it.
  • Invariant: a property that must hold in every reachable state.
  • Reachable state: any configuration the model can get into from Init.
  • Bound: the maximum loop unwind / input size the checker considers.
  • Counterexample: a concrete input that breaks your statement — the tool's most useful output.
  • unsat: no counterexample exists in the checked domain. That is a proof, within the domain.
