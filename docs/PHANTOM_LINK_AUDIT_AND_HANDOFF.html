1. Executive summary

Bottom line: Phantom Link is a real prototype with a working custom OLED UI, a working variable-width font pipeline, and a Base-6 codec whose arithmetic is correct. It is not yet a link, a handshake, or an encrypted device. The single biggest problem is not a missing feature — it is that the repository contains two divergent firmwares, and the one labeled TX is an older, protocol-incompatible snapshot that cannot type or send. Fix that first; everything else follows.

UI & asset pipeline AMBER

128×64 SH1106 driver, 1024-byte framebuffer, variable-width font, joystick and multi-tap input exist. Numeric page is half-wired; text rendering has a y-offset bug; boot art is unused.

Base-6 codec GREEN

The high/low math is correct for A–Z. The transport is A–Z only, so space, digits, and punctuation corrupt. Two digits cannot represent the 49-character UI (48 glyphs + space); three digits can.

Link & handshake RED

No HELLO, no ACK, no peer address, no link state, no heartbeat, no timeout, no CRC. Sends are blind and the serial monitor can print success while the packet dies in lwIP.

Encryption RED

Not implemented. PhantomPacket and calculate_crc() are dead code. The README’s “encrypted / XOR cipher / packed struct / sync word” claims are ahead of the firmware.

Reproducibility AMBER

No license, CI, tests, wiring doc, or UI image converter. The only PNG script generates fonts. Two duplicate trees and tracked intermediate images.

Documentation truth RED

README contradicts the code on AP role, static IP, encryption, framing, and “raw RF.” The Bible’s immediate-next-step list is two milestones stale.

What is genuinely working

  • Framebuffer + SH1106 SPI driver. 1024-byte buffer, page writes, +2 column offset, pixel/box/bitmap primitives. The three UI images are exactly 1024 bytes each; the font table is internally consistent at 179 bytes / 49 widths / 49 offsets.
  • The Base-6 arithmetic. high = idx / 6, low = idx % 6, decoded = 'A' + high*6 + low is correct for A–Z. The screenshot sequence PONG PING SYNC SYNC PONG PING END decodes to 3,0 / 2,2 / 3,0 = S O S.
  • UI/input foundation. Joystick navigation, two buttons with pull-ups and debounce, multi-tap group logic, alpha/numeric pages, and PNG-to-C assets exist.
  • Role plumbing in intent. The comment SET TO 1 FOR THE JANK BOX (AP) / SET TO 0 FOR THE RX PICO (STA) is the correct architecture. The implementation just drifted into two folders.

What must happen next, in one sentence

Collapse both boards onto one main.c with an IS_AP build flag, port the input loop to the AP build, then add HELLO/HELLO_ACK/LINK_PING/LINK_PONG with peer learning and a 3-second heartbeat before touching encryption or true MAC-layer SFO.

3. Architecture decision: one firmware, two roles

3.1 The truthful version of the AP/STA rule

The CYW43439 and the Pico SDK expose two Wi-Fi roles: AP (host the network) and STA (join it). The SDK has no supported ad-hoc/IBSS path, so exactly one board must be the AP. That part of the earlier advice is true.

What is not true is that this requires two codebases. AP/STA is a radio-link role. TX/RX is what a packet is doing. They are orthogonal. Both boards carry the same BOM and run the same transceiver, so either can type, send, receive, decode, and render. The correct architecture is one firmware, one flag:

2.4 GHz Wi-Fi (private AP, no router) ┌──────────────────────────┐ ┌──────────────────────────┐ │ Barebones · AP role │ │ Jank Box 5000 · STA role│ │ OLED + joystick + buttons│◄──────►│ OLED + joystick + buttons│ │ UDP :4444 │ │ UDP :4444 │ │ HELLO_ACK, LINK_PING │ │ HELLO, LINK_PONG │ └──────────────────────────┘ └──────────────────────────┘ same main.c, IS_AP=1 same main.c, IS_AP=0

For the PoC, the user confirmed Barebones = AP (host) and Jank Box 5000 = STA (client). The earlier audit recommendation (Jank Box = AP) is superseded. Both units now carry the identical BOM: SH1106 OLED, PSP joystick on ADC0/ADC1, and SELECT/DELETE/BACK on GP14/GP15/GP12. IS_AP selects only the Wi-Fi role; the OLED, ADC, button, codec, parser, and screen paths are unconditional, so both boards type, send, receive, decode, and render. Wi-Fi bring-up is non-blocking, so the UI and controls run while the STA joins. The code does not care which physical board plays which role; only the UF2 differs.

3.2 One source, two build targets

Move the RX main.c to the canonical firmware project, replace the hard #define IS_AP with a default, and let CMake define it per target:

// main.c
#ifndef IS_AP
#define IS_AP 1          // safe default; CMake overrides per target
#endif
# CMakeLists.txt
add_executable(phantom_link_ap  main.c)
target_compile_definitions(phantom_link_ap  PRIVATE IS_AP=1)

add_executable(phantom_link_sta main.c)
target_compile_definitions(phantom_link_sta PRIVATE IS_AP=0)

foreach(tgt phantom_link_ap phantom_link_sta)
  target_link_libraries(${tgt} pico_stdlib pico_cyw43_arch_lwip_poll
                              hardware_spi hardware_adc)
  target_include_directories(${tgt} PRIVATE ${CMAKE_CURRENT_LIST_DIR})
  pico_enable_stdio_usb(${tgt} 1)
  pico_enable_stdio_uart(${tgt} 0)
  pico_add_extra_outputs(${tgt})
endforeach()

This produces phantom_link_ap.uf2 and phantom_link_sta.uf2 from one source. Both builds run the same UI, input, codec, and parser; only the Wi-Fi bring-up differs. “Identical firmware” here means identical source and behavior, not byte-identical UF2s: the role constant is compiled in. The implementation stores it in a static const bool is_ap and keeps the OLED, ADC, button, codec, and parser paths outside every role conditional. A future single-binary option is to read SELECT at boot (held = AP, released = STA) and set the same runtime variable; for the PoC, two deterministic targets are easier to debug.

The SDK 2.3.1 cyw43 build is compiled with CYW43_NETUTILS=0, so the AP has no DHCP server. The STA therefore stops DHCP and uses the fixed address 192.168.4.2/24, gateway 192.168.4.1. This is a PoC transport decision; a product build should add a DHCP server or make the address configurable.

3.3 Why the split happened, and why it must be closed now

The TX folder was built at 16:16 on 11/15; the RX folder was last edited at 17:21. All Base-6 work landed in RX after the TX snapshot. Every hour spent maintaining two trees from here will recreate the same drift. The repository must have one firmware source before the handshake work starts, or the next feature will land on one board only again.

5. Deep dives and reference designs

5.1 The two-firmware fork, and the one-source migration

The diff is not cosmetic. It is a protocol fork:

DecoderHigh/low accumulator, 'A' + high*6 + low'A' + packet_id, one frame per character

Do not patch the TX tree in place. Every fix you make there would need to be made again in RX, and the two would drift a third time. The migration is: promote RX main.c to the canonical firmware, parameterize the role, build two targets, verify both boards, then archive the TX tree. The old TX .uf2 should be copied somewhere outside the repo before any clean build.

Migration steps

  1. Create firmware/ at the repo root (or rename Phantom_Link_rx to firmware). Move main.c, oled.h, font_ui.h, alpha_ui.h, numeric_ui.h, boot_ui.h, lwipopts.h, and CMakeLists.txt into it. Keep the PNG sources in assets/.

  5. Only then delete Phantom_Link_tx from the working tree. Keep its last .uf2 in artifacts/uf2/ (gitignored) as a rollback.

5.2 Base-6 capacity, the 49-code alphabet, and the codec

Base-6 means six possible symbols per frame. Each frame carries log₂(6) ≈ 2.585 bits. The number of frames per character determines the alphabet size:

DigitsCodesBits per characterFrames per characterCoverageVerdict
162.581Six symbolsNot enough
2365.172A–Z + 0–9 exactlyCurrent PoC; cannot represent space or punctuation
32167.75348 drawable glyphs + space (49); full printable ASCII if desiredRECOMMENDED

Two digits are mathematically elegant — 36 codes exactly covers A–Z and 0–9 — but the UI's target character set is 48 drawable glyphs plus space: 49 characters. Space, =, +, -, ., ,, ?, !, (, ), [, ], and " cannot be represented. The current clamp turns all of them into 'A'. Three digits solve it and still fit the SFO concept: the receiver just accumulates three symbols instead of two. SOS becomes nine frames instead of six; at 80 ms per frame that is 720 ms, which is fine for a PoC.

Canonical glyph table

// 49 transport codes: the 48 drawable glyphs plus space.
// The leading space is code 0; A is 1. The renderer keeps its own
// character-to-font-index map, so this order need not match it.
static const char GLYPHS[] =
    " ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789=+-.,?!()[]\"";

static int code_from_glyph(char c) {
    if (c == '\0') return -1;
    const char *p = strchr(GLYPHS, c);
    return p ? (int)(p - GLYPHS) : -1;
}

static char glyph_from_code(int code) {
    if (code < 0 || code >= (int)sizeof(GLYPHS) - 1) return '?';
    return GLYPHS[code];
}

The font table has 48 drawable glyphs; space is a transport-only code. oled_draw_custom_string() already advances five pixels for an unknown character, so it renders space correctly without a glyph.

Encode one character into three Base-6 symbols

int code = code_from_glyph(c);
if (code < 0) code = code_from_glyph('?');   // unknown glyph fallback

int d0 = code / 36;          // 0..1
int d1 = (code / 6) % 6;     // 0..5
int d2 = code % 6;           // 0..5

send_symbol(d0);
send_symbol(d1);
send_symbol(d2);

Decode three symbols into one character

static int sym_acc = 0;
static int sym_count = 0;

// packet_id is 0..5, resolved from the six packet names.
sym_acc = sym_acc * 6 + packet_id;
if (++sym_count == 3) {
    char c = glyph_from_code(sym_acc);
    if (rx_index < 63) {
        rx_buffer[rx_index++] = c;
        rx_buffer[rx_index] = '\0';
    }
    sym_acc = 0;
    sym_count = 0;
}
Token collision. The six symbols are PING, ACK, SYNC, PONG, DATA, READY. Do not use ACK as a handshake reply: it is symbol index 1. Use HELLO_ACK, LINK_PING, LINK_PONG, which start with letters outside the alphabet and are checked before symbol decoding.

Reliability note. Three-symbol grouping still desynchronizes if a frame is lost. For the PoC, add a 500 ms inter-symbol timeout that resets sym_acc/sym_count, and send END with the expected character count. A full msg_id/seq header belongs in the encryption phase, not before the handshake works.

5.3 Handshake, peer learning, heartbeat, and link state

The handshake is four control tokens outside the Base-6 alphabet. The STA initiates; the AP replies and learns the peer address from the packet. After that, both sides heartbeat and both can send data.

STA (Jank Box 5000) AP (Barebones) | | |------ HELLO ----------------------------------->| |<----- HELLO_ACK --------------------------------| | link_state = LINK_UP on both sides | | | |------ LINK_PING ------------------------------->| |<----- LINK_PONG --------------------------------| |<----- LINK_PING --------------------------------| |------ LINK_PONG ------------------------------->| | | | every 1 s; any valid packet updates last_heard| | no packet for 3 s -> LINK_DOWN on both | | | |------ Base-6 data symbols + END --------------->| |<----- Base-6 data symbols + END ----------------|

Exact packet parser

static bool pkt_eq(const struct pbuf *p, const char *tok) {
    size_t n = strlen(tok);
    return p->tot_len == n && memcmp(p->payload, tok, n) == 0;
}

This replaces strncmp(payload, token, p->len). It rejects zero-length packets, prefixes like PIN, and suffix garbage. p->payload assumes one contiguous pbuf; datagrams this small normally are, but for correctness check p->next == NULL or copy with pbuf_copy_partial() into a 16-byte buffer before comparing.

Receive callback

static void udp_recv_callback(void *arg, struct udp_pcb *pcb,
                              struct pbuf *p, const ip_addr_t *addr, u16_t port) {
    if (!p) return;
    uint32_t now = now_ms();

    if (pkt_eq(p, TOK_HELLO)) {
        peer_ip = *addr;
        peer_port = port;
        have_peer = true;
        last_heard_ms = now;
        link_state = LINK_UP;
        udp_send_to(TOK_HACK, &peer_ip, peer_port);
        printf("LINK UP: HELLO from %s:%u\n", ipaddr_ntoa(addr), port);
    } else if (pkt_eq(p, TOK_HACK)) {
        peer_ip = *addr;
        peer_port = port;
        have_peer = true;
        last_heard_ms = now;
        link_state = LINK_UP;
        printf("LINK UP: HELLO_ACK from %s:%u\n", ipaddr_ntoa(addr), port);
    } else if (pkt_eq(p, TOK_PING)) {
        last_heard_ms = now;
        udp_send_to(TOK_PONG, addr, port);
    } else if (pkt_eq(p, TOK_PONG)) {
        last_heard_ms = now;
        link_state = LINK_UP;
    } else {
        decode_symbol(p);   // Base-6 data path, §5.2
    }

    pbuf_free(p);
}

5.5 The font pipeline bug and the missing UI converter

This is the subtle one. png2c.py finds glyphs by scanning for all-black columns. That works for most letters, but the double-quote is two vertical marks separated by a black column. The scanner treats the gap as a glyph boundary and emits two one-pixel glyphs. Evidence:

  • font_char_count = 49, but oled_draw_custom_string() maps only indices 0–47.
  • font_widths[47] = 1, font_widths[48] = 1; font_offsets[47] = 177, [48] = 178.
  • The last two image bytes are 0x0C, 0x0C — the two halves of the quote.
  • The renderer maps " to index 47, so it draws only the first half. Index 48 is orphaned.

Fix the quote and the count

// Desired: one 3-column glyph (mark, gap, mark) at index 47.
// font_image: ... 0x0C, 0x00, 0x0C
// font_widths[47] = 3
// Remove index 48. font_char_count = 48.
// font_image length becomes 180; offsets 0..47 stay unchanged (last offset 177).

Better: make the scanner manifest-driven. Add a sidecar file or a header row that declares the glyph order and width, then assert the generated count matches. A positional font where one stray pixel shifts every subsequent character is a debugging trap. At minimum:

_Static_assert(sizeof(font_widths) / sizeof(font_widths[0]) == 48,
               "font table must contain 48 glyphs");
_Static_assert(sizeof(font_offsets) / sizeof(font_offsets[0]) == 48,
               "font offsets must contain 48 glyphs");

5.6 Fixing the OLED text engine

The current function has two independent bugs. First, int start_page = y / 8; throws away y % 8, so y = 30 draws at row 24. Second, it assigns oled_buffer[...] = col_data;, which erases the background instead of drawing over it. The result is text that sits six pixels too high and chews holes in the box art.

Correct renderer

void oled_draw_custom_string(int x, int y, const char *text) {
    int page  = y / 8;
    int shift = y % 8;
    int cursor_x = x;

    while (*text) {
        char c = *text++;
        int index = glyph_index(c);          // your existing map, §5.2/§5.5
        if (index < 0 || index >= font_char_count) {
            cursor_x += 5;
            continue;
        }

        int w = font_widths[index];
        int off = font_offsets[index];

        for (int col = 0; col < w; col++) {
            uint8_t d = font_image[off + col];
            int sx = cursor_x + col;
            if (sx < 0 || sx >= 128 || page < 0 || page >= 8) continue;

            oled_buffer[page * 128 + sx] |= (uint8_t)(d << shift);
            if (shift && page + 1 < 8)
                oled_buffer[(page + 1) * 128 + sx] |= (uint8_t)(d >> (8 - shift));
        }
        cursor_x += w + 1;
    }
}

Add a fill helper

void oled_fill_rect(int x, int y, int w, int h, bool on) {
    for (int yy = y; yy < y + h; yy++) {
        for (int xx = x; xx < x + w; xx++) {
            int page = yy / 8, bit = yy % 8;
            if (xx < 0 || xx >= 128 || page < 0 || page >= 8) continue;
            if (on) oled_buffer[page * 128 + xx] |=  (1 << bit);
            else    oled_buffer[page * 128 + xx] &= ~(1 << bit);
        }
    }
}

Choose a real text region

The current art has PREV: at rows 0–7 and CURR: at rows 8–15; the selectable grid starts at row 20. There is no free 8-pixel row. Two clean options:

  1. Repurpose the header (recommended for the PoC). Each frame, fill rows 0–15 off, draw the message at y = 0 (wrap at ~21 characters), and draw the multi-tap preview at y = 8. This simultaneously implements PREV:/CURR: and stops text from touching the grid.
  2. Edit the art. Reserve a 16-pixel message strip, move the grid down, and regenerate all three headers. More work, cleaner long-term layout.

5.7 Non-blocking transmit state machine

The send path must never own the CPU. Replace the loop of sleep_ms(100) calls with a state machine ticked from the main loop. One symbol per 80–100 ms; cyw43_arch_poll() runs every iteration.

typedef enum { TX_IDLE = 0, TX_SYMBOL, TX_END } tx_phase_t;

static tx_phase_t tx_phase = TX_IDLE;
static char     tx_buf[64];
static int      tx_len = 0;
static int      tx_pos = 0;
static int      tx_digit = 0;
static uint32_t tx_next_ms = 0;
static uint8_t  tx_msg_id = 0;
void start_send(void) {
    if (link_state != LINK_UP || msg_length == 0 || tx_phase != TX_IDLE) return;
    memcpy(tx_buf, current_message, msg_length + 1);
    tx_len = msg_length;
    tx_pos = 0;
    tx_digit = 0;
    tx_msg_id++;
    tx_phase = TX_SYMBOL;
    tx_next_ms = now_ms();
    printf("TX start msg=%u len=%d\n", tx_msg_id, tx_len);
}
// Call every main-loop iteration, after cyw43_arch_poll().
void tx_tick(void) {
    uint32_t now = now_ms();
    if (tx_phase == TX_IDLE || now < tx_next_ms) return;

    if (tx_phase == TX_SYMBOL) {
        int code = code_from_glyph(tx_buf[tx_pos]);
        if (code < 0) code = code_from_glyph('?');

        int div = (tx_digit == 0) ? 36 : (tx_digit == 1) ? 6 : 1;
        int sym = (code / div) % 6;
        send_symbol(sym);                 // dummy_packets[sym], checks err_t
        tx_next_ms = now + 80;

        if (++tx_digit == 3) {
            tx_digit = 0;
            if (++tx_pos >= tx_len) tx_phase = TX_END;
        }
    } else if (tx_phase == TX_END) {
        send_control(TOK_END);            // optionally "END:<id>:<len>"
        tx_next_ms = now + 80;
        tx_phase = TX_IDLE;
        printf("TX done msg=%u\n", tx_msg_id);
        // Keep current_message for retry; clear it on DELETE or after an app ACK.
    }
}

DELETE during TX should cancel: tx_phase = TX_IDLE; tx_pos = 0; tx_digit = 0; and keep the draft. If link_state drops, abort the same way and print TX aborted: no link.

Why this also improves SFO fidelity. A blocking send makes the inter-frame timing depend on the OLED refresh and the button handler. A state machine with a single send point per tick gives you a stable, measurable cadence — which is exactly what a future timing/frame-order channel needs. The PoC’s packet-name alphabet is the warm-up; the timing discipline starts here.

6. Phase-by-phase remediation plan

Do the phases in order. Each phase has a single deliverable and a hard “done” test. Phase 3 is the handshake-first milestone; do not start Phase 4 until Phase 3 is green on both boards. Do not start Phase 8 until Phase 6 passes. The methodology is: freeze → unify → handshake → data transport → UI truth → hardware proof → document → crypto/stealth.

Phase 0 — Freeze and preserve the working state

Goal: Make it impossible to lose the only working Jank Box image or the current source state.

Phase 3 - Handshake, peer learning, heartbeat

Goal: Both boards know whether the link is up, learn each other’s address from the traffic, and refuse to send into the void. This is the handshake-first milestone; the full data codec is Phase 4.

  1. Replace strncmp with the exact pkt_eq parser in §5.3. Check every udp_sendto/pbuf_alloc return; log failures.
  2. Add the control tokens, link_state enum, peer_ip/peer_port, and the last_heard/last_ping timers from §5.3.
  3. STA sends HELLO every 1 s until HELLO_ACK; AP stores the source address and replies to it. Prefer unicast after the first handshake; do not rely on broadcast.
  4. Both sides send LINK_PING every 1 s and reply LINK_PONG; any valid packet updates last_heard_ms.
  5. Timeout at 3 s: set LINK_DOWN, print LINK LOST, blink/off the LED.
  6. Gate SEND on LINK_UP; if down, print NO LINK and keep the draft.
  7. Log state transitions only, not every packet; drive the CYW43 LED from link_state.

Done when: cold boot produces HELLO -> HELLO_ACK -> LINK UP on both; unplugging the STA produces LINK LOST on both within 3 s; replugging recovers without a reboot; SEND is refused while down.

Appendix E — Glossary

TermMeaning in this project
APWi-Fi Access Point; hosts the private network. Exactly one board must be AP.
STAWi-Fi Station; joins the AP. The other board is STA.
Base-6Six-symbol alphabet; each frame carries log₂(6) ≈ 2.58 bits.
SFOStegoFrameOrder; encoding data in the order/choice of frames. Current PoC uses packet names; true SFO uses MAC-layer frame order/timing.
SymbolOne of the six packet names: PING, ACK, SYNC, PONG, DATA, READY.
GlyphOne displayable character in the 48-glyph font table. Space is a transport-only code, not a glyph.
FrameOne UDP packet carrying one symbol (or a control token).
FramebufferThe 1024-byte page-major OLED image buffer.
pbuflwIP packet buffer; must be freed after the callback/send.
HandshakeHELLO/HELLO_ACK + heartbeat; proves both peers are alive and learns addresses.
PoCProof of concept; the handshake-first milestone, not the finished product.
