The security layer, layer by layer

Read time: 8 minutes. One win: you can write the datasheet security section without overclaiming.

1. The threat model first

This is a two-party link (ADR 0004). Membership is physical possession of a board. There is no secure element, so a PSK in firmware is a pairing boundary, not a secret against someone holding the hardware. There is no forward secrecy and no independent audit. These limits belong in the datasheet.

3. The primitive: Speck128/128

A 32-round ARX block cipher (add–rotate–xor) from NSA research. We use the reference implementation guide's key schedule and KAT vectors. Words are little-endian — the paper's word order confused our first test, so the host KAT pins the exact bytes. See NSA Implementation Guide and proto_crypto.c.

4. Keys: role-based, not sender-relative

The 32-byte PSK feeds a CMAC-based KDF. Two labels produce two directional keys: 0x01 for AP→STA and 0x02 for STA→AP. Both boards derive the same key for a given direction. Our first implementation used "my send / my receive", so the two boards disagreed and every HELLO failed — the fix made keys role-based.

5. Encryption and authentication order

Encrypt-then-MAC: CTR-encrypt the padded payload, then CMAC the 18-byte header (AAD) together with the ciphertext. The receiver verifies the tag before decrypting; a bad tag increments crypto and drops the frame without touching session state. The tag is the first 8 bytes of the CMAC, MSB-first, following RFC 4493.

CTR keystream must never repeat for one key. The nonce is 0x01 || seq(4) || 0^7; sequence is unique per direction within a session.

6. Identity: BSSID lock plus key confirmation

SSID alone is ambiguous. The STA now joins only the enrolled AP BSSID using cyw43_wifi_join(..., bssid, channel), then verifies the connected BSSID at runtime with cyw43_wifi_get_bssid(). A mismatch increments bssid, logs BSSID MISMATCH, and disconnects. Only after Layer-2 identity succeeds does app-layer key confirmation prove the peer knows the PSK.

7. What we deliberately do not claim

  • No MAC-layer SFO or raw-frame injection (CYW43439 cannot do it).
  • No "covert" or "audited" language before hardware acceptance.
  • No forward secrecy, no secure element, no protection against physical flash access.
  • The AEAD slot is reserved, not implemented — the suite is Speck CTR+CMAC today.

8. Retrieval practice

Q1. A bad CMAC tag causes:

A. DROP BEFORE DECRYPT
B. DECRYPT THEN WARN

A — verify before decrypt; no plaintext surfaces and session state is untouched.

Q2. Directional keys are derived by:

A. SENDER RELATIVE LABELS
B. ROLE BASED LABELS

B — AP→STA (0x01) and STA→AP (0x02) must match across both boards.

Q3. BSSID lock protects against:

A. DUPLICATE SSID HOTSPOTS
B. PHYSICAL FLASH THEFT

A — it binds Layer 2 identity; flash theft still reveals the PSK.
